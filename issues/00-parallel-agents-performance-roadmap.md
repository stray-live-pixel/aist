# Roadmap: плавная работа параллельных агентов

## Контекст

Сейчас разные чаты могут запускать агентов параллельно, но интерфейс и daemon начинают лагать. По анализу прямой глобальной блокировки запуска нет: проблема в слишком тяжёлом и слишком частом обновлении состояния.

Главные источники лагов:

1. На каждое runtime-событие daemon дополнительно отправляет `state.changed` без `chatId`.
2. Extension из-за `state.changed` без `chatId` часто делает полный refresh всех чатов.
3. Все refresh-события проходят через одну общую очередь `refreshQueue`, поэтому обновления разных чатов ждут друг друга.
4. `ChatRepository` пересобирает индекс всех чатов на горячих изменениях вроде `activity`, `activityDetail`, `modelRequest`.
5. Incremental `chat.patch` может срабатывать слишком поздно: `upsert` уже успевает вызвать full state broadcast.
6. Activity/model-request события могут приходить часто и провоцировать файловые записи, JSON-RPC события и webview обновления.

## Общие правила для всех задач

- Перед изменениями читать указанные файлы полностью.
- Не менять публичные контракты без необходимости.
- Не смешивать несколько задач в одной реализации.
- Для каждой задачи добавить unit/regression tests.
- После задачи запускать релевантные тесты и `typecheck`.
- Если полный `typecheck` или все тесты падают из-за соседней проблемы, зафиксировать это в отчёте и приложить focused-тесты.

## Базовые команды проверки

Уточнить реальные scripts в `package.json`, затем использовать релевантные команды. Минимально ожидаемые проверки:

```bash
npm test -- --run <focused-test-file>
npm run typecheck
```

Если в проекте нет `typecheck`, использовать ближайший существующий script из `package.json` и явно указать это в отчёте.

## Целевой результат всей серии

При двух одновременно работающих чатах:

- второй чат не ждёт refresh первого чата;
- runtime-события одного чата не вызывают полный refresh всех чатов;
- webview получает маленькие patch-сообщения вместо полного состояния там, где это возможно;
- файловое хранилище не пересобирает индекс всех чатов на каждый progress/status update;
- UI остаётся отзывчивым при streaming activity двух агентов.
