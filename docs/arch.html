AIST / VS Code extension architecture

Webview → Daemon → Core AI agent

Эта страница объясняет, что происходит после нажатия Send в VS Code: React webview отправляет команду в extension host, extension пересылает её в долгоживущий JSON-RPC daemon, а daemon запускает core runtime агента, модель, инструменты и approval-flow.

Источник правды Состояние чатов и рантайма живёт на стороне daemon/core, а webview только отображает state и отправляет действия.
Главный транспорт UI vscode.postMessage и webview.postMessage между React webview и extension host.
Главный backend transport Локальный socket / named pipe с newline-delimited JSON-RPC 2.0 сообщениями.

Что происходит после Send

Основной сценарий вызова агента из VS Code.

  1. Пользователь вводит prompt в Composer. Компонент вызывает agentActions.ask(prompt), а facade отправляет { type: 'ask', prompt } через vscode.postMessage.
  2. Extension host принимает сообщение. webview.onDidReceiveMessage передаёт команду в AgentController.handleWebviewMessage.
  3. Контроллер выбирает daemon route. Для ask он берёт surface.getChatId(), синхронизирует legacy API key и вызывает daemonRuntime.ask(chatId, prompt).
  4. Bridge отправляет JSON-RPC. VscodeDaemonRuntimeBridge делает config.update для актуальных настроек и затем chat.ask по локальному socket.
  5. Daemon принимает run. AistDaemonServer.chatAsk проверяет busy-state, вызывает runtime.startAsk, регистрирует active run и сразу отвечает { accepted: true, runId }.
  6. Core runtime выполняет agent loop. AgentRuntimeService добавляет user message, собирает context, вызывает модель, исполняет tools, обрабатывает approval и повторяет цикл до финального ответа.
  7. Daemon транслирует события. Runtime events сохраняются в run repository и уходят как JSON-RPC notification event: run.started, message.appended, tool.*, model.response, run.finished.
  8. Extension обновляет локальный chat store. Bridge по событию делает chat.get или state.get, обновляет DaemonChatStore и уведомляет AgentController.
  9. Webview получает patch. AgentController.postChatPatch мапит daemon event в chat.patch, отправляет во все surfaces, а React применяет applyAgentPatch.

Core agent loop

Что именно делает AI runtime после принятия chat.ask.

Итерационный цикл модели и инструментов

Core runtime специально отделён от VS Code: storage, model transport, tools, context providers и UI callbacks передаются как адаптеры. Поэтому один и тот же агентный цикл можно запускать в daemon, CLI и unit-тестах.

1. Accept runПроверка prompt, busy-state, создание runId, AbortController и telemetry.
2. Prepare contextSystem prompt, история чата, memory block, repo/editor context и context governance.
3. Request modelOpenRouter или Codex transport, streaming deltas, lifecycle status, retry до 3 попыток.
4. Execute toolsЕсли модель вернула tool calls, ToolRunner выполняет их, пишет tool messages и ждёт approval при необходимости.
5. FinalizeКогда tool calls закончились, сохраняется assistant answer, usage, history и run.finished.

Транспортные границы

Webview IPC
Команды UI идут через vscode.postMessage, ответы — через webview.postMessage.
Daemon JSON-RPC
Extension и daemon говорят newline-delimited JSON-RPC 2.0 по socket.
Core adapters
Daemon внедряет repositories, model client, tool runner, context providers и event sink.
Events
Runtime progress возвращается как daemon notifications, затем как webview patches.

Главная идея архитектуры: webview — это тонкий интерактивный клиент, extension host — адаптер VS Code и маршрутизатор surfaces, daemon — единый workspace backend с долговременным состоянием, а core runtime — чистый агентный цикл с моделью, инструментами, approval и событиями. Поэтому активный run может продолжаться даже при переподключении UI, а разные webview surfaces получают одинаковую картину через state и patches.
Сгенерировано по текущему коду AIST: VS Code webview, daemon JSON-RPC и core AgentRuntimeService.
