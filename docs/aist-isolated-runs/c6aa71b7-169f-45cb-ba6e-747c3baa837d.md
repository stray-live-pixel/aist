# AIST isolated run c6aa71b7-169f-45cb-ba6e-747c3baa837d

## Задача

Доработать isolated agents так, чтобы рабочая копия агента не была связана с компьютером, на котором запускается Docker: контейнер должен сам клонировать GitHub-репозиторий, устанавливать AIST, создавать ветку, выполнять доработки и отдавать состояние в локальный UI/daemon.

## Реализация

- Isolation lifecycle переведён с host git worktree на автономный Docker container workspace.
- Локальный daemon теперь только резолвит remote/base metadata, стартует контейнер без bind mount, пишет chat/events/session state и наблюдает за выполнением.
- В контейнере выполняется bootstrap: установка базовых утилит при необходимости, `git clone`, checkout рабочей ветки, `npm install`, `npm run build:cli`, `npm link --force`.
- Filesystem tools, bash, project tools и custom skills isolated runtime выполняются внутри контейнера против `/workspace`.
- Git finalize перенесён в контейнер: commit/push/PR metadata читаются из `docker exec` stdout и сохраняются в `IsolationSessionSummary`, поэтому VS Code продолжает видеть прогресс и итог даже без host checkout.
- Для будущего удалённого запуска сохранён локальный канал состояния: chat/run events остаются в daemon repositories и JSONL isolation events; container/remote runner может отдавать такие же lifecycle/log/runtime events в daemon bridge.
