# Изолированный запуск 6d2159e9-e9b5-4723-9353-203e3d9f6beb

## Задача

Исправить удаление workflow на странице управления Workflow: после клика «Удалить» и подтверждения workflow должен удаляться из файловой системы и из интерфейса, а во время ожидания удаления кнопка должна показывать loader и быть неактивной.

## Изменения

- Добавлено pending-состояние удаления workflow в `FlowsPage`: выбранная кнопка «Удалить» показывает spinner и текст «Удаляем…», кнопки строки блокируются на время операции.
- Webview теперь отправляет в extension не только `id`, но и описание выбранного workflow; extension удаляет native workflow directory из текущего workspace напрямую, чтобы подтверждённое удаление точно меняло `.aist-agent/autonomous/flows`.
- Extension отправляет в webview результат операции `autonomous.operation` для статусов `done`, `cancelled` и `error`, чтобы UI мог снять pending даже при отмене подтверждения или ошибке.
- После успешного удаления extension дополнительно отправляет свежий autonomous state в webview перед событием завершения операции, чтобы список workflow обновлялся сразу.
- Backend delete-contract расширен до `DeleteAutonomousFlowInput`, при этом старый `flowId` fallback сохранён.
- Добавлены переводы `autonomous.workflows.deleting` для RU/EN.
- Добавлены regression-тесты: core удаление каталога workflow и extension helper удаления из текущего workspace при stale `sourcePath`.
