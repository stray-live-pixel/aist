# Этап 3 — Самопроверка кода

С полным контекстом реализационного этапа: сделай критическое код-ревью
файла `game.html`. Изменения в этом этапе **не вносить** — только список
наблюдений.

## Что проверить

1. **Физика платформера**: рыцарь не проваливается сквозь платформы, прыжок
   возможен только с поверхности, горизонтальное движение не ломает коллизии?
2. **Управление**: стрелки/WASD/Space не скроллят страницу во время игры, нет
   залипания клавиш после Restart или потери фокуса?
3. **Враги**: патрулируют в заданных пределах, не улетают за уровень, касание
   стабильно приводит к поражению?
4. **Ключи и ворота**: ровно 5 ключей, счётчик обновляется, ключи исчезают,
   ворота открываются только после `5/5`, победа засчитывается только при входе
   рыцаря в открытую зону ворот?
5. **Restart flow**: Restart полностью сбрасывает позицию игрока, врагов,
   собранные ключи, статус ворот, таймеры и overlay.
6. **Ассеты**: простые картинки действительно сгенерированы внутри `game.html`
   и применяются в отрисовке; нет внешних URL, мёртвых ассетов и пустых
   placeholder-ов.
7. **Canvas и адаптивность**: canvas резкий на retina, корректно масштабируется
   CSS-ом, UI не перекрывает важные игровые объекты.
8. **Чистота кода**: дубли, мёртвые ветки, неиспользуемые переменные, слишком
   длинные функции.

## Формат отчёта

Список пронумерованных пунктов, каждый: проблема (1 строка) + предлагаемая
правка (1–2 строки). Без дисклеймеров и общих фраз. Если всё хорошо — так и
напиши.
