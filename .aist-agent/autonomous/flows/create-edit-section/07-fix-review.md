# Задача этапа

Исправить блокирующие замечания из `06-review.md` и подготовить секцию к финальным проверкам.

Используй `Project Context Pack` из `01-planning.md` и конкретные замечания `06-review.md`. Не расширяй scope и не перечитывай базовые правила проекта без необходимости.

# Что сделать

1. Разобрать результат review

- Найди все `blocker` и обязательные замечания.
- Если review явно разрешил merge без blockers, не делай косметических изменений: зафиксируй, что исправления не требуются.
- Если замечание неоднозначное, сверяйся с кодом и `DEVELOPMENT.md`, а не расширяй scope.

2. Внести исправления

- Исправляй только проблемы, указанные в review, и тесно связанные с ними регрессии.
- Не переписывай архитектуру заново, если review не требует этого явно.
- Для каждой правки проверь соответствие:
  - `additionalData.type` вместо индексов;
  - `SafeHtmlReplacer` для текстов;
  - `PreparedImage` для изображений;
  - `HomeAction` внутри wrapper-элемента;
  - `MetricsTemplate`/`TemplateBuilder` и `isMeta: true` для мета-шорткатов;
  - `dataTestId` в пропсах и `data-test-id` в DOM.

3. Синхронизировать артефакты

- Если менялись роли шорткатов или `additionalData`, обнови `README.md`, `__default-props__` и stories.
- Если менялся `SectionViewType` или config, проверь, что `targetPath`, `dir`, `Component` и `Skeleton` согласованы.

4. Итог этапа

- Верни короткий список исправленных замечаний.
- Отдельно перечисли оставшиеся риски или причины, почему замечание не исправлено.
- Не объявляй проверки пройденными, если они будут запускаться только на `08-tests.md`.
