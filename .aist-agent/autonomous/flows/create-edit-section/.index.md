# Flow создания/доработки секции

Сценарий применения:

- `01-planning.md` собирает детальный `Project Context Pack` по проекту и план текущей секции, чтобы остальные этапы не повторяли базовое исследование;
- для новой секции: `02-scaffold.md` делает каркас + регистрацию типа + подключение в config;
- для доработки существующей: `02-scaffold.md` только валидирует готовность каркаса и не меняет реестр по умолчанию.

Применять к:

- новой секции в `src/widgets/SP/...` (или раздел `src/pages/.../sections`, если секция не домашняя);
- доработке существующей секции при изменении структуры шорткатов, action/стилей/метрик.

Ветки размещения:

- `sectionDomain: SP` — основной путь `src/widgets/SP/<SectionName>/`;
- `sectionDomain: pages/...` — путь выбирается по локальным примерам внутри конкретного модуля `src/pages/<module>/sections/...`; не переносить автоматически в `src/widgets/SP`.

Базовые принципы:

- Для секции нужен контроллер на `CommonSectionController` (или аналогичный контейнер).
- Шорткаты разделяются по `additionalData.type`, не по индексу.
- Все рендеримые тексты через `SafeHtmlReplacer`.
- Изображения через `PreparedImage`.
- Клики и важные интерактивы через `MetricsTemplate`/`HomeAction`.
- `HomeAction` размещается внутри wrapper-элемента, чтобы не ломать layout.
- `data-test-id` на значимые DOM узлы.
- Не добавлять `useMemo`/`memo` заранее без измеренной проблемы.
