# Задача этапа

Подготовить каркас новой секции до бизнес-реализации.

Используй `Project Context Pack` из `01-planning.md` как основной источник правил, путей, эталонов и команд. Не перечитывай базовые файлы проекта повторно без конкретной причины.

# Что сделать

1. Определи сценарий

- Если это создание новой секции, выполняй все шаги этого этапа полностью.
- Если это доработка существующей секции:
  - проверь, что базовый каркас уже существует;
  - если каркас уже есть, не меняй `section-view-type.ts` и `features/sections/config.ts`, зафиксируй это и переходи к сути задачи;
  - если каркас отсутствует, создай минимальный каркас и подключение в `config` только после согласования с `01-planning.md`.

2. Создать структуру файлов и базовую сборку

- Сформировать каркас в `targetPath` из `01-planning.md`:
  - для `sectionDomain: SP` обычно `src/widgets/SP/<SectionName>/`;
  - для `sectionDomain: pages/...` следуй локальному паттерну `src/pages/<module>/sections/...`.
- Минимальный каркас:
  - `<SectionName>.tsx` (root-заглушка секции);
  - `index.ts`;
  - `__default-props__/index.ts` с минимальным `defaultConfiguration`, если секция новая;
  - `components/Skeleton` (минимальный рабочий скелетон);
  - `types.ts` (минимальные локальные типы, если нужны);
  - `controllers/SectionController.tsx` (минимальный passthrough через `CommonSectionController`);
  - при необходимости `components/index.ts`.
- Каркас должен быть корректно импортируемым и не ломать сборку без наполнения бизнес-логики.

3. Подключить новый тип секции в реестр

- Для нового типа добавь `DynamicSectionViewType` в `src/shared/types/section-view-type.ts`.
- Добавь секцию в `src/features/sections/config.ts`:
  - ключ `SectionViewType.<...>`;
  - `dir` в формате ближайших существующих секций (обычно путь до root-файла или папки секции);
  - `Component` и `Skeleton` через `dynamic(...)` с импортом из `index.ts`.

4. Проверка каркаса

- Проверить, что после шага 2-3 сборка может найти секцию по её типу.
- Проверить, что `index.ts` экспортирует `default` секции и `Skeleton`.
- Проверить, что `defaultConfiguration` содержит валидные `shortcuts`/`metaShortcuts`, даже если они пустые.
- Зафиксировать список созданных/добавленных файлов.

5. Результат этапа

- Для новой секции: список новых/изменённых файлов и подтверждение в `section-view-type.ts` + `features/sections/config.ts`.
- Для доработки существующей: список проверок готовности каркаса к интеграции и перечень файлов, которые не трогали.
