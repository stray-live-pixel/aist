# Задача этапа

Подготовить документацию секции в формате `README.md`, полностью готовую к пополнению репозитория.

Используй `documentationContract`, `shortcutContract` и `Section Plan` из `Project Context Pack` в `01-planning.md`. Не перечитывай базовые правила проекта повторно, если не нашёл противоречие в коде.

# Что нужно сделать

1. Создай/обнови `README.md` в папке секции.
2. Схема README должна включать:

- Назначение секции, `targetPath`, `SectionViewType` и точку подключения в `features/sections/config`.
- Список ролей шорткатов по `additionalData.type` (для каждой роли:
  - название роли,
  - где настраивается в админке,
  - примеры значений/назначения).
- Поля `additionalData`, если используются (название поля + тип + влияние на рендер/метрики).
- Примеры заполнения для ключевых шорткатов.
- Описание поведения/краевых случаев:
  - какие поля обязательные,
  - что произойдёт при их отсутствии,
  - ограничение по обязательности `additionalData.type`.
- Блок `Known issues / Частые ошибки` (минимум 3 пункта из практики интеграций).

3. Язык и стиль:

- Русский, понятный и короткий.
- Без избыточной теории, только правила для контента/админки/эксплуатации.
- Формат markdown с явными заголовками и списками.

4. Проверки перед закрытием этапа:

- README отражает фактические типы шорткатов из кода.
- README синхронизирован с `__default-props__`, storybook и контроллером.
- Нет несоответствий между секцией/сторибуком и README (хотя бы по именам ролей и типу секции).
- Нет «заглушечных» формулировок без практической пользы (напр. «настраивается как обычно» без конкретики).
