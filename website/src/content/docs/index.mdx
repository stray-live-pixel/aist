<section class="landing-section landing-split">
  <div>
    <p class="landing-eyebrow">Everyday developer flow</p>
    <h2>From prompt to patch without leaving VS Code.</h2>
    <p>
      AIST keeps the whole loop in the editor: chat in the sidebar or an editor tab, let the agent inspect files,
      approve shell commands when needed, and review final changes in a familiar diff.
    </p>
  </div>
  <div class="landing-steps">
    <div><strong>1</strong><span>Open a chat and describe the bug, refactor, test, or feature.</span></div>
    <div><strong>2</strong><span>AIST gathers workspace context and plans the safest next actions.</span></div>
    <div><strong>3</strong><span>You approve risky tools, review diffs, and keep full ownership.</span></div>
  </div>
</section>

<section class="landing-section">
  <p class="landing-eyebrow">Built for serious repositories</p>
  <h2>Everything a coding agent needs to be useful in production work.</h2>
  <div class="landing-grid">
    <article class="landing-card">
      <h3>Workspace tools</h3>
      <p>Read files, search symbols, run focused commands, and edit project files with configurable permissions.</p>
    </article>
    <article class="landing-card">
      <h3>Approvals and safety</h3>
      <p>Read-only tools can run fast, while shell commands and mutations ask for confirmation unless you explicitly relax the rules.</p>
    </article>
    <article class="landing-card">
      <h3>Agent modes and skills</h3>
      <p>Create project instructions, custom modes, and reusable skills so AIST follows the way your team actually works.</p>
    </article>
    <article class="landing-card">
      <h3>Autonomous runner</h3>
      <p>Define longer project flows for repeatable agent work while preserving logs, artifacts, and review points.</p>
    </article>
    <article class="landing-card">
      <h3>Persistent context</h3>
      <p>Project memory, chat compaction, and workspace storage keep useful context available without mixing secrets into the repository.</p>
    </article>
    <article class="landing-card">
      <h3>Daemon backend</h3>
      <p>A CLI daemon owns runs, tools, model requests, and events, keeping the VS Code extension thin and responsive.</p>
    </article>
  </div>
</section>
