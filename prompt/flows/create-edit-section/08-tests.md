# Задача этапа

Сформировать и прогнать минимально достаточный чеклист проверки для секции.

Используй `validationContract` из `Project Context Pack` в `01-planning.md`, а также итоги `06-review.md` и `07-fix-review.md`. Не подбирай команды заново, если они уже зафиксированы в первом этапе.

# Обязательные проверки (локально/CI)

1. Качество и типы

- Сценарий A: изменены только `README.md`, `*.stories.tsx`, `__default-props__`:
  - `npm run storybook:build`.
- Сценарий B: менялись файлы секции и/или связанные конфиги:
  - `npm run lint:js:ci`
  - `npm run type-checking:root`
  - если менялись `*.scss`: `npm run lint:css:ci`
  - если менялись `src/shared/types/section-view-type.ts` или `src/features/sections/config.ts`: `npm run type-checking:configs`.

2. Unit / интеграционные юниты

- Если добавлял/менял утилиты (например `getSectionSettings`, `parseAdditionalData`, `split-shortcuts`):
  - добавить или обновить тесты.
- Запуск:
  - `npm run test -- src/widgets/SP/<SectionName>`
  - либо целевой путь к новому `.test.ts`/`.test.tsx`.

3. Storybook и визуальная проверка

- Проверить `*.stories.tsx` сборку вручную через `npm run storybook:build`.
- Если есть Hermione-наборы для секции в проекте — запустить соответствующие проверки по вашему пайплайну.
- Если Storybook/Hermione не запускались, явно указать причину и остаточный риск.

4. Ранговый регресс

- Проверить, что новые/измененные shortcuts корректно проходят рендер в:
  - светлой и тёмной теме;
  - desktop/mobile (если есть мобильная story);
  - состояние скелетона.

5. Поведенческие проверки

- Отслеживание кликов и actions:
  - action-треки должны отправляться с `HomeAction` и метаданными шортката;
  - мета-шорткаты без `isMeta: true` недопустимы.

# Итоговый вывод для этого этапа

- Сформируй список:
  - выполненных проверок;
  - результатов (успех/провал и причина);
  - блокирующих не пройденных тестов (если есть).
- Не называй проверку успешной, если команда не запускалась.
