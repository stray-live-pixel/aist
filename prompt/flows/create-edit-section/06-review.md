# Задача этапа

Проведи аудит уже реализованной секции и верни четкий вывод: можно мержить или нет.

Сначала используй `Project Context Pack` из `01-planning.md` как чеклист ожидаемых правил и эталонов. Повторно открывай базовые источники только для спорных мест или точной сверки.

# Критерии проверки (обязательны)

1. Архитектурные нормы

- Рутовый компонент без сложной бизнес-логики.
- Есть `SectionController`/контроллерная прослойка (если нужна логика секции).
- Логика получения/подготовки данных изолирована в `hooks` или `utils`.

2. Типизация и интеграция

- `SectionViewType` используется из `src/shared/types/section-view-type.ts` + `config`.
- Секция корректно подключена в `src/features/sections/config.ts`.
- Экспорты `index.ts` и `Skeleton` корректны.

3. Принципы шорткатов и additionalData

- Нет логики «первый по индексу».
- Разделение `shortcuts/metaShortcuts` сделано явно и детерминировано.
- Для типизации ролей шорткатов используется `additionalData.type`.

4. Рендер и безопасность

- Проверить `SafeHtmlReplacer` для всех новых/измененных текстовых участков.
- Проверить `PreparedImage` для новых источников изображений.
- Проверить `HomeAction` + метрики (`MetricsTemplate`/`TemplateBuilder`) на интерактиве.
- Проверить, что `HomeAction` находится внутри wrapper-элемента, а не ломает grid/flex-layout.
- Проверить `isMeta: true` там, где мета-шорткат трекается как мета.

5. Стили и атрибуты

- `data-test-id` есть на важных DOM-узлах секции.
- `dataTestId` используется в пропсах, а не как `data-test-id` в объекте.
- Пользовательские стили применяются поверх дефолтов (`...userStyles` после базовых стилей).

6. Статика и контент

- `README.md`, stories и `defaultConfiguration` присутствуют.
- `__default-props__` содержит именованные `IShortcut`-константы + агрегат `defaultConfiguration`, а `additionalData` задан через `JSON.stringify`.
- Для текстов в stories есть корректный `SectionViewType` и необходимые `shortcutsStatus/metaShortcutsStatus`.
- В stories есть минимум по светлой и тёмной теме (если секция уже поддерживалась ранее в обоих видах).

7. Риски и пробросы

- Отсутствующие `additionalData`/кривые `parse` не ломают рендер;
- пустые массивы шорткатов не приводят к падениям;
- сохранение устойчивости к null/undefined у опциональных полей.
- Нет преждевременной мемоизации (`memo`/`useMemo` без понятной причины).

8. Соответствие контракту этапов

- Название секции и `targetPath` совпадают с артефактами `01-planning.md`.
- Если это новая секция: `section-view-type.ts` и `features/sections/config.ts` изменены только в согласованных точках.
- Если это доработка: отсутствуют нежелательные изменения в `section-view-type.ts` и `features/sections/config.ts` без явной нужды.
