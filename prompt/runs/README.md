# Runs

Batch-режим: один пакет задач, каждая со своим flow. Запуск:

```sh
./agent-auto.sh --run <name> [--engine claude|codex] [--html|--ui] [--dry-run]
```

## Структура

```
runs/<name>/
├── .index.md         ← конфиг рана: dir + список задач
├── issues/           ← md-файлы задач, ждут выполнения
│   ├── 1-add-button.md
│   ├── 2-fix-typo.md
│   └── 3-refactor.md
└── done/             ← сюда переезжают завершённые задачи (создаётся автоматически)
```

## .index.md

```markdown
---
title: Sprint 42 backlog # опционально, для удобства
dir: /Users/me/projects/myrepo # рабочий каталог агента (--cwd)
repeat: 2 # опционально: повторить весь список N раз
tasks:
  - task: issues/1-add-button.md
    flow: example
  - task: issues/2-refactor.md
    flow: code-review
    repeat: 10 # опционально: повторить эту задачу N раз
  - task: issues/3-fix-typo.md
    flow: example
---
```

- `dir:` — путь к репозиторию, где надо вести работу. Может быть абсолютным
  (с `~` тоже сработает) или относительным к каталогу `runs/<name>/`.
- `repeat:` (run-level, опционально) — внешний цикл. Весь список задач
  выполнится N раз. По умолчанию `1`.
- `tasks:` — упорядоченный список. Порядок выполнения = порядок в этом списке.
- `task:` — путь к md-файлу с описанием задачи (относительно `runs/<name>/`).
- `flow:` — имя flow из `flows/<flow>/` (см. [flows/README.md](../flows/README.md)).
- `repeat:` (task-level, опционально) — внутренний цикл. Конкретная задача
  выполнится N раз подряд внутри одной outer-итерации. По умолчанию `1`.

## Как это работает

1. Оркестратор итерируется по `tasks:` `run.repeat` раз (внешний цикл).
2. Для каждой задачи внутри одной outer-итерации делается `task.repeat` запусков
   (внутренний цикл) — каждый запуск это отдельная сессия `./agent-auto.sh
--flow <flow> --cwd <dir> "<тело task.md>"`. Тело файла задачи приклеивается
   преамбулой к каждому стейджу выбранного flow.
3. Файл задачи переезжает из `issues/` в `done/` (с сохранением подкаталогов)
   **только** после **последней** outer-итерации, при условии что все
   `task.repeat` внутренних запусков в этой outer-итерации прошли успешно.
4. Если хотя бы один внутренний запуск упал — задача в этой outer-итерации
   считается failed, оркестратор идёт к следующей задаче. На следующей
   outer-итерации задача будет повторена. В конце печатается список тех
   задач, которые так и не доехали до `done/`.

Пример иллюстрации цикла для `run.repeat: 2`, два task'а с
`task.repeat: 1` и `task.repeat: 3`:

```
outer 1: t1 (×1), t2 (×3)        ← пока ничего в done/
outer 2: t1 (×1), t2 (×3)        ← обе задачи переезжают в done/ при успехе
```

Итого `t1` выполнится 2 раза, `t2` — 6 раз.

## Зачем повторы

- `task.repeat: N` — итеративные улучшения одного и того же артефакта (например,
  «прогнать рефакторинг по этому модулю 10 раз», каждая итерация смотрит на уже
  изменённый код и улучшает его дальше).
- `run.repeat: N` — пройти по всему набору задач несколько раз (например, набор
  «найди-и-почини» эвристик прогнать 3 раза, чтобы вычистить остатки).

## Флаги монитора

`--html`, `--ui`, `--dry-run`, `--port` и `--engine` пробрасываются к каждой задаче.
С `--html` для каждой задачи откроется отдельная вкладка браузера —
это нормально, сервер на каждом запуске свой и поднимается/гасится автоматически.

## Пример

```
runs/sprint-42/
├── .index.md
├── issues/
│   ├── 1-fix-login.md
│   └── 2-add-loader.md
└── done/                 # появится после первой успешной задачи
```

```sh
./agent-auto.sh --run sprint-42 --html
```

Codex-вариант:

```sh
./agent-auto.sh --run sprint-42 --engine codex --html
```
